# wav404 site: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A one-page GitHub Pages site that takes SP-404SX owners to the wav404 download.

**Architecture:** A gated Go test renders real UI screenshots from the fixture card into `assets/screenshots/`. `site/index.html` is a static page with inline CSS. `.github/workflows/pages.yml` copies the screenshots into the site and deploys it.

**Tech Stack:** Go + Fyne test canvas (screenshots), plain HTML/CSS, GitHub Actions Pages.

**Spec:** `docs/superpowers/specs/2026-11-23-site-design.md`

## Global Constraints

- No Roland logos, photos or artwork. "SP-404SX" appears only for compatibility, and the page carries the "Not affiliated with Roland" disclaimer.
- Screenshots come only from the synthetic fixture card.
- Download URLs: `https://github.com/davideluzi/wav404/releases/latest/download/wav404-macos-universal.dmg` and `…/wav404-windows-amd64.zip`.
- Requirements: macOS 13 or later (universal); Windows 10 or later (64-bit).
- Accent `#ffb020`, graphite background, system fonts. The page must work at 375 px width with no horizontal scroll.
- English copy.

## Review Focus

- The latest-release URLs 404 until the first `v*` tag exists. The page states that the buttons need a release; the user tags after the site is up.
- At phone width, wide screenshots must scale down and not overflow (`img { max-width: 100% }`).
- Without the screenshots copied in (opened locally from `site/`), the images break. The preview copies them the same way the workflow does.
- Dark-only page: the text contrast on graphite must stay readable (muted text no darker than #9a9a9a on #1b1c1e).
- The Pages source must be set to GitHub Actions, or the deploy job fails. The user is told.

### Task 1: Site screenshots

**Files:** Create `cmd/wav404/site_shots_test.go`; output `assets/screenshots/{main,playing,drop,import}.png`.

**Interfaces:** Produces `TestRenderSiteShots`, gated by `WAV404_SITE_SHOTS=<dir>` (skipped when unset). It uses `newTestGUI`, `selectJ5`, `doubleTap`, `center` and `g.dragOver`. The window is 1040×604 with the canvas scale set to 2.

- [ ] Write the test. The four states are:
  - `main`: bank J, J5 selected;
  - `playing`: J5 double-tapped;
  - `drop`: dragOver on tile 7 of bank J;
  - `import`: `runInBackground` with a progress of 0.62 and the label `J9 ← breakbeat_92bpm.wav`, held open by a channel while capturing.

  Each state goes to `<dir>/<name>.png`.
- [ ] Run `WAV404_SITE_SHOTS=$PWD/assets/screenshots go test ./cmd/wav404 -run SiteShots`. Expect 4 PNGs of 2080×1208. Check them by eye.
- [ ] Run `go test ./cmd/wav404`. Expect PASS, with the test skipped.
- [ ] Commit `Add site screenshots rendered from the real UI`.
